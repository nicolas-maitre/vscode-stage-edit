# Changelog

All notable changes to Stage Edit are recorded here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses
[semantic versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- `stageEdit.promptOnKeypress` turns the type-to-enable prompt off on its own, leaving the
  editor title button and the commands working. Needed by anyone using a modal-editing
  extension: keybindings are resolved before the `type` command, so while those bindings are
  live a Vim user pressing `j` in a staged diff would raise the prompt instead of moving the
  cursor.
- Marketplace metadata: icon, repository, issue tracker, gallery banner, and `capabilities`
  declaring that the extension needs a trusted, non-virtual workspace. Writing the working tree
  runs `git checkout-index`, which applies the clean/smudge filters a repository defines, and
  those are arbitrary commands.
- GitHub Actions for CI across Linux, macOS and Windows, and a tagged release that attaches the
  `.vsix` to a GitHub release. Publishing to the Visual Studio Marketplace is commented out
  until a publisher account exists; publishing to Open VSX skips itself while its token is
  unset.

### Fixed

- The user's `git.path` setting is now honoured. Previously a bare `git` was always spawned, so
  anyone whose git is not on `PATH` — common on Windows — got an unexplained `ENOENT` while the
  rest of their Git integration worked fine.
- Path comparisons and map keys are folded on case-insensitive filesystems. VS Code may hand a
  provider a URI whose case differs from the one the extension produced, which could split one
  file into two cache entries on macOS and Windows.

## [0.4.0]

### Added

- A third option in the unstaged-changes dialog: **Only Update Index**, which stages the edit
  and leaves the file on disk untouched. Overwriting puts the two back in step and so stops the
  asking; updating the index only leaves them apart by design, so it asks again on the next
  save.

## [0.3.0]

### Added

- `askWhenDirty`, now the default for `stageEdit.apply.syncWorkingTree`. The staged copy and the
  file on disk are kept in step, and a save that would overwrite unstaged work stops and asks
  rather than letting the two drift apart.

### Changed

- The working-tree decision is resolved in full before `update-index` runs, so a cancelled save
  is never half-applied.
- Live mode holds back on a file with unstaged changes instead of raising a dialog mid-keystroke.

## [0.2.0]

### Added

- `stageEdit.apply.syncWorkingTree`, replacing the earlier boolean. Old `true`/`false` values in
  settings keep working.

### Fixed

- A file was wedged on the read-only diff for the rest of the session after editing was enabled
  for it. Two swaps could start at once, the loser was recorded as a permanent failure against a
  URI that is identical on every reopen, and the prompt then declined to ask because the file was
  already enabled. Transient outcomes are no longer remembered, and the prompt now opens the
  editable view instead of asking when the file is already enabled.
- The working tree is written with `git checkout-index` rather than the blob bytes, so
  clean/smudge filters, line endings and the executable bit stay correct. Writing blob bytes into
  a repository with `text eol=crlf` produced an LF file and an immediate phantom diff.

## [0.1.0]

Initial version: staged changes become editable from the Source Control diff view, backed by a
writable `stage-edit:` filesystem provider over the Git index.
